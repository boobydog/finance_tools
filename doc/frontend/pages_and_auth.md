# 画面一覧・認証仕様

## 画面(ルート)一覧

Next.js App Router(`frontend/src/app/`)。

| ルート | 説明 |
|---|---|
| `/` | リダイレクト専用(サーバーコンポーネント)。無条件に`/dashboard`へ`redirect`する。実質的なランディングページは存在しない。 |
| `/login` | ログイン画面。ユーザー名/パスワード入力フォーム。 |
| `/dashboard` | ダッシュボード(ログイン後の既定遷移先)。 |
| `/admin` | 管理者設定画面(**現状はプレースホルダー**、タグ/スクリーニンググループのマスタ管理を今後追加する想定と明記されているのみ)。ナビゲーションメニューには意図的に含めず、直接URLでのみ到達可能。 |
| `/stocks` | 銘柄管理一覧(候補/保有中/売却済/除外のタブ切替、検索・並び替え・ページング)。 |
| `/stocks/[code]` | 銘柄詳細(チャート・ステータス変更・売買記録・損切り/利確判定詳細・関連ニュース)。 |
| `/entry-monitor` | 買入タイミング判定一覧。 |
| `/exit-monitor` | 損切り・利確判定一覧(統合表示)。 |
| `/settings/rules` | 判定基準設定(スクリーニングルール編集/テクニカルスコア設定/取引コスト設定の3タブ)。 |
| `/api/auth/[...nextauth]` | NextAuthのカタックオールルート(認証処理そのもの、画面ではない)。 |

### `/dashboard` の詳細要件

- USD/JPY為替レートカード(直近日の値、データ出典を明記)
- バッチ実行ログテーブル(処理名・ステータス・リトライ回数・更新日時。ステータスに応じて色分け: SUCCESS=緑, FAILED=赤, RETRYING=黄, RUNNING=青)
- 関連ニュース一覧(タイトル・出典・公開日時、外部リンク)。TDnet(適時開示情報)から`scripts/tdnet_client.py`が取得し、`GET /api/news`経由で表示する。
- 全て読み取り専用の表示画面。ローディング中は各セクション個別にスピナー表示。

### `/admin` の詳細要件

現状はプレースホルダー画面(見出しと説明文のみ、データ取得なし)。将来的にタグ・スクリーニンググループなどのマスタデータ管理機能を追加する想定の置き場として確保されている。認証を有効化した場合、未ログインユーザーはこのページへのアクセス時も`/login`へリダイレクトされる。

## 認証仕様

### 方式

NextAuth(Credentials Provider、JWTセッション戦略)。**単一の管理者アカウント**(ユーザーテーブルなし、環境変数で認証情報を管理)を想定する。マルチユーザー・ロール管理は要件に含めない。

### 認証の有効/無効切替

環境変数`ENABLE_AUTH`(既定`false`)でルート保護のON/OFFを切り替えられること。無効時はルートガードを完全にスキップする(開発・個人利用時に認証を省略できるようにするため)。

### ルート保護

Next.js 16の`proxy.ts`(旧`middleware.ts`相当、Next 16での名称変更)でルートガードを実装する。

- `ENABLE_AUTH !== "true"`の場合は何もしない(全ルート通過)。
- `ENABLE_AUTH === "true"`の場合、JWTトークンを検証し、無効なら`/login?callbackUrl=<元のパス>`へリダイレクトする。
- `/api/auth/*`, `/login`, 静的アセット配信パスは、このガードの対象から除外すること(除外しないと無限リダイレクトになる)。

### ログインフロー

1. `/login`でユーザー名/パスワードを送信。
2. サーバー側(NextAuthの`authorize`)で、環境変数`ADMIN_USERNAME`/`ADMIN_PASSWORD`との単純な文字列比較で認証する(DBルックアップなし)。
3. 一致すればJWTセッションを発行し、`callbackUrl`(または既定で`/dashboard`)へ遷移する。
4. 不一致ならエラーメッセージを表示する。

> 実装メモ: これは意図的に簡易な「暫定実装」であり、本番相当のマルチユーザー運用にする場合はユーザーテーブル・パスワードハッシュ化・ロール管理への置き換えが前提となる。

### 環境変数

| 変数名 | 用途 |
|---|---|
| `ENABLE_AUTH` | 認証機能そのもののON/OFF(既定false) |
| `NEXTAUTH_URL` | NextAuthのコールバック先ベースURL |
| `NEXTAUTH_SECRET` | JWT署名・検証用のシークレット |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 単一管理者アカウントの認証情報 |

## 共通レイアウト

- ルートレイアウト(`layout.tsx`): 言語設定(`lang="ja"`)、フォント、メタデータ(タイトル・説明)を設定し、Providers → AppShellの順にラップする。
- Providers(`providers.tsx`): SessionProvider → QueryClientProvider(TanStack Query) → ThemeProvider(MUI、既定ダークモード)の順にネストする。
- AppShell(共通ナビゲーション): 上部AppBar(タイトル+市場開場状態インジケータ)+ サイドナビゲーション(ダッシュボード/銘柄管理/買入タイミング判定/損切り・利確判定/判定基準設定の5項目。`/admin`は含めない)。デスクトップは常時表示のドロワー、モバイルは開閉式。
