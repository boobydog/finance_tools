# 候補スクリーニング(自動候補化)

## 要件

未設定(候補・保有・除外いずれも未設定)の銘柄を、一定の基準を満たした場合に自動で「候補(interested)」ステータスへ反映する。**2系統**を独立して実装すること。

候補選定は**ファンダメンタルズ指標**(ROE・自己資本比率・売上高成長率・営業利益率・時価総額)を主に用い、「投資対象として妥当な範囲か」をふるいにかける。タイミングの良し悪し(テクニカル)は別機能([買入タイミング判定](trade_judgment.md))で判定するため、ここでは扱わない。

## 系統A: スクリーニングルール(A/B/C分類)による候補化

- 各有効な[スクリーニンググループ](../../requirements/02_glossary.md)の`rule_purpose='candidate'`ルールのうち、**分類A・分類Bのいずれかに1つでも該当すると、そのグループの候補としては失格**とする(A・Bは同じ強さのブロック条件、内部的にはOR結合)。
- 分類Cは候補判定には使用しない(入力自体はできるが判定に影響しない、参考情報)。
- 失格しなかった銘柄は「候補」となり、**根拠グループ名をタグとして自動付与**する。このタグが、後続の買入タイミング/損切り/利確判定で「どのグループの基準を適用するか」を決めるキーになる(詳細は [`trade_judgment.md`](trade_judgment.md) のグループ解決方針)。
- 既にステータスが設定されている銘柄(手動含む)は上書きしない。
- グループを無効化した場合、そのグループのみを根拠に候補になっていた銘柄はステータス・タグをリセットし、有効なグループのみで再評価し直す。他の有効グループにも該当する銘柄や、手動でステータスを設定した銘柄には触れない。
- 該当パラメータの実データが欠測(NULL)の場合、そのルールは「判定不能」としてスキップする(ブロック扱いにしない)。

### 参考値の設計例(時価総額セグメント別)

小型株・中型株・大型株のように時価総額でセグメント分けし、各セグメントに適した財務基準の範囲を設定する。「範囲」は同一パラメータに対する`lte`条件(下限)と`gte`条件(上限)のペアで表現する(いずれかに該当したら失格 = 範囲外なら失格)。

| 項目 | 小型株の例 | 中型株の例 | 大型株の例 |
|---|---|---|---|
| ROE(%) | 10.0 〜 213.6 | 8.0 〜 80.0 | 5.0 〜 40.0 |
| 自己資本比率(%) | 40.0 〜 97.85 | 35.0 〜 95.0 | 30.0 〜 90.0 |
| 売上高前期比(%) | 20.0 〜 98.45 | 8.0 〜 40.0 | 0.0 〜 20.0 |
| 売上高営業利益率(%) | 10.0 〜 20.19 | 8.0 〜 18.0 | 8.0 〜 25.0 |
| 時価総額(百万円) | 60 〜 30,000 | 100,000 〜 1,000,000 | 1,000,000 〜 50,000,000 |

セグメント区分の目安: 中型株はTOPIX Mid400、大型株はTOPIX100・市場平均ROE(10.3%)を参考に設定している。具体的な最新値は稼働中システムの設定画面で確認すること。

### 追加のスクリーニング項目(投資家スタイル別グループ向け)

以下は候補スクリーニング(分類B)で利用可能なパラメータとして追加済み(いずれもルール未設定のグループには影響しない)。

| param_key | 意味 | 算出方法 |
|---|---|---|
| peg_ratio | PEGレシオ(派生値) | `forward_per ÷ eps_growth`。候補スクリーニングのクエリ側で都度計算する(DBには保存しない)。ピーター・リンチの基準で1以下なら割安とされる。`eps_growth`が0以下の銘柄はNULL(判定不能)として扱う |
| free_cash_flow | フリーキャッシュフロー | `stock_metrics.free_cash_flow`(百万円)。yfinanceが算出済みの値をそのまま採用し、営業CFとCapExを自前で減算しない(CapExの符号表記の違いによる符号反転バグを避けるため) |
| revenue_cagr_5y | 売上高5期CAGR | EDINET有価証券報告書の「経営指標等の推移」(直近5期)から算出した年平均成長率(%)。詳細は[継続性データ(EDINET連携)](#継続性データedinet連携)を参照 |
| net_income_cagr_5y | 当期純利益5期CAGR | 同上。始点・終点いずれかが赤字の場合はNULL(判定不能) |
| consecutive_revenue_growth_years | 売上高成長の連続年数 | 直近から遡って売上高が前年比で増加し続けている年数(0〜4) |
| consecutive_profit_years | 黒字の連続年数 | 直近から遡って当期純利益が黒字であり続けている年数(0〜5) |

### 継続性データ(EDINET連携)

バフェット/リンチ流の候補スクリーニングで重視される「過去数期にわたる継続性」を判定パラメータとして使えるようにするため、EDINET(金融庁の開示システム)の有価証券報告書から法定の「経営指標等の推移」(直近5期分の売上高・当期純利益等)を取得する。

- **発見方法**: EDINET公式の書類一覧API(日付ごとに取得)を、レスポンスに含まれる`secCode`(証券コード)で追跡銘柄と突き合わせる方式。第三者ラッパーAPIには依存しない。
- **取得範囲**: 銘柄ごとに最新の有価証券報告書1件を取得するだけで、直近5期分(当期・前期・前々期・三期前・四期前)が一括で手に入る(法定開示のため)。**10期分(10年)への拡張は未対応**(5年前の書類を追加取得する発見手段が別途必要なため)。
- **訂正報告書への対応**: 訂正有価証券報告書(doc_type_code=130)は元の書類と異なるdoc_idで提出されるため、日次スキャンで「未取込のdoc_id」として自然に検知し、該当期間のデータを上書きする。
- 実装: `scripts/edinet_client.py`(`sync_filings`)。CLI: `edinet-backfill`(手動、全追跡銘柄への一括初回取得)、`edinet-sync`(cron、日次で直近数日分を再スキャン)。
- DBテーブル: `financial_results`(決算期別の生データ)、`edinet_filings`(取込済み書類の台帳)、`stock_metrics`(継続性指標を非正規化して保存、候補スクリーニングから高速参照するため)。

## 系統B: テクニカルスコアによる自動候補化

- 対象銘柄の[テクニカルスコア](technical_score.md)(6要素合計)が**しきい値以上**、かつステータス未設定の銘柄を「候補」として反映する。
- 系統Aとは完全に独立しており、こちらで候補になった銘柄にはタグが付かない(後続のグループ解決では、タグ不一致としてデフォルトグループにフォールバックする)。
- しきい値変更時は、旧しきい値未満になった候補をリセットして再評価する(reconcile)。
- 実際のスコアに応じて表示用の階層タグ(例:「高スコア(60点以上)」)を全銘柄に同期する。階層は複数段階(例: 100/80/60/40/20点以上)用意し、スコアが下がればタグも下位に切り替わるようにする。

### 参考値

- 自動候補化しきい値: 60点以上(設定変更可能)
- 表示用タグ階層: 100 / 80 / 60 / 40 / 20点以上
