# finance_tools

日本株売買予測ツール（仮）

## セットアップ

認証情報はテンプレートファイル(`*.example`)をコピーして作成してください(いずれもgit管理対象外です)。

```
cp .env.example .env
cp mysql/client.cnf.example mysql/client.cnf
cp mysql/secrets/root_password.txt.example mysql/secrets/root_password.txt
cp mysql/secrets/password.txt.example mysql/secrets/password.txt
```

各ファイルの値を必要に応じて書き換えたうえで、`mysql/client.cnf` と `mysql/secrets/*.txt` の
パスワードは一致させてください(`mysql/secrets/password.txt` が実際にDBへ設定される
アプリ用ユーザーのパスワードです)。

```
make up
```

### 1. システムの戦略概要

本システムは、個別株の裁量判断に頼りすぎず、**機械的・再現可能なルールで「買い時」「損切り」「利確」を判定する**ことを目指した投資支援ツールである。基本方針は以下の通り。

#### 1.1 候補選定はファンダメンタルズ、タイミングはテクニカルという2段階アプローチ

候補スクリーニングでは、ROE・自己資本比率・売上高成長率・営業利益率・時価総額といった**ファンダメンタルズ指標**で「投資対象として妥当な範囲か」をふるいにかける。そのうえで、買入タイミング判定では、MA25上抜け・出来高急増・決算サプライズといった**テクニカル指標**で「今が実際に仕掛けるタイミングか」を判定する。ファンダメンタルズの質とテクニカルのタイミングを分離して評価する設計になっている。

#### 1.2 「確立モメンタム戦略」— 逆張り・底打ち狙いではない

買入タイミング判定は、複数のシグナル(トレンド転換・出来高急増・決算の市場予想超え)の重複確認により、**既に上昇トレンドが確立した銘柄を狙う**モメンタム戦略を採用している。まだ底打ちしていない逆張り・反転狙いの銘柄は対象外である。一方で、単純な「上がっている銘柄を追いかける」だけでは高値掴みのリスクがあるため、RSI過熱・MA25乖離しすぎ・前日比急騰・上抜け直後(だまし)といった**過熱・単日急騰を検知する除外条件**を設け、モメンタムの「初動」を捉えつつ「最終局面での飛び乗り」を避けるバランスを取っている。

#### 1.3 銘柄の時価総額規模(小型/中型/大型)に応じた基準の調整

小型株・中型株・大型株では値動きの荒さ(ボラティリティ)やモメンタムの持続期間が異なるため、候補選定の財務基準・出来高倍率のしきい値・PER過熱判定・保有期間上限などをセグメント別に調整している(詳細は各章の「現状の参考値」を参照)。一般に、小型株は値動きが荒くモメンタムの反転も早いため基準を厳しめ・保有期間を短めに、大型株は機関投資家の資金流入で値動きが安定しモメンタムが持続しやすいため基準を緩やかめ・保有期間を長めに設定している。

#### 1.4 損切りは価格・ファンダメンタルズ・スコアの複合基準

損切り判定は、単純な下落率だけでなく、(1) 銘柄自身のヒストリカルボラティリティ(HV)に連動して動的に変化する下落率基準、(2) 営業利益・EPS成長率の悪化といったファンダメンタルズの悪化、(3) 購入時からのテクニカルスコアの悪化、という3系統の基準を組み合わせている。値動きの荒い銘柄には広めの許容幅を、穏やかな銘柄には早めの損切りラインを自動的に設定する。

#### 1.5 利確は「主観的なターゲットプライス」に依存しすぎない複数軸判定

利確判定は、目標株価到達・PER過熱・トレイリングストップ発動・MA25クロスアンダー(トレンド反転)という価格・テクニカルベースの軸に加え、**保有期間の上限に達したら損益に関わらず機械的に決済する**という第3の判定軸を独立して持たせている。これは、モメンタム効果が一定期間で減衰しやすいという考え方(確率論的なモメンタム戦略)を踏まえ、「もう目標に達したから売ろう」という主観的なタイミング判断だけに頼らず、規律的な出口ルールを併用する設計である。また、額面上は利確条件を満たしていても、手数料・税金を差し引いた実質損益がプラスでなければ利確シグナルとして扱わない「純損益ゲート」を設けている。トレイリングストップの許容下落率もグループ(小型/中型/大型)ごとに調整でき、値動きの荒い銘柄ほど広め、安定した銘柄ほど狭めに設定している。

#### 1.6 複数回の売買・NISA/課税口座の分離管理

同一銘柄を複数回に分けて買い増し・売却することを前提に、購入価格・保有数は取引履歴全体から加重平均・合計で算出する。また、NISA口座と特定・一般口座は税制上別勘定であるため、口座種別ごとに残存数量・取得単価を分けて管理し、損益計算(手数料・税引後の想定純損益)も口座種別ごとに計算して合算する。

### 2. 対象銘柄の範囲

**日本株(東京証券取引所上場銘柄)を対象とし、既定の銘柄ユニバースは日経225(日経平均株価)構成銘柄である。**

- 新規銘柄の発見(候補スクリーニング・テクニカルスコアリングの対象探索)は、日経225の構成銘柄(日本経済新聞社の公式サイトから取得)を対象に行う。銘柄コードは`{証券コード}.T`形式(例: `7203.T`)で管理しており、`.T`は東証上場銘柄であることを示す。
- 日経225の構成銘柄は入れ替わりがあるため、`is_nikkei225`フラグをバッチ処理のたびに最新の構成銘柄リストと同期する。
- 一度「候補」「保有中」「除外」等のステータスが手動またはシステムによって設定された銘柄は、その後日経225の構成銘柄から外れても引き続き追跡対象になる(`user_stock_status`に行がある銘柄は常に追跡対象)。
- したがって実際の追跡対象銘柄は「日経225構成銘柄」∪「過去に何らかのステータスが設定された銘柄」の和集合となる。
- 実装: `batch/scripts/nikkei225.py`(構成銘柄取得)、`batch/scripts/target_symbols.py`(対象銘柄群の解決)

### 3. 全体アーキテクチャ

#### 3.1 スクリーニンググループとルール

判定基準は「スクリーニンググループ」単位(例: 小型株・中型株・大型株・デフォルト)で管理する。1つのグループは、用途(`rule_purpose`)ごとに4種類のルールセットを持つ。

| 用途(rule_purpose) | 内容                             |
| ------------------ | -------------------------------- |
| `candidate`        | 候補スクリーニング(自動候補化)用 |
| `entry_timing`     | 買入タイミング判定用             |
| `loss_cut`         | 損切り判定用                     |
| `profit_taking`    | 利確判定用                       |

各ルールは「分類(A/B/C)」「項目(param_key)」「演算子(以上/以下/等しい)」「値」「値の種別(固定値 or HV倍率)」を持つ。**同じ分類内の複数条件は常にOR(いずれか1つで成立)**。分類同士の組み合わせ方(該当時にどう扱うか)は用途ごとに異なり、単純なAND/ORの指定機能ではない(詳細は各章を参照)。

#### 3.2 どのグループの基準を使うか(グループ解決)

1. 銘柄が持つタグ(候補になった際の根拠グループ名)のうち、有効なグループに一致するものがあれば、そのグループの基準を使う(複数該当時は`group_id`が小さい方を優先)。一致したグループの基準のみが使われ、そのグループにルールが無くてもデフォルトグループへはフォールバックしない。
2. タグが一致するグループが無ければ、`is_default=true`の削除不可グループ(デフォルト)にフォールバックする。
3. 有効なグループが1件も無ければ判定対象外(未設定)。

#### 3.3 現状のスクリーニンググループ一覧

| group_id | 名称       | 有効 | デフォルト | 候補スクリーニング | 買入シグナル数しきい値 | 保有期間上限 |
| -------- | ---------- | ---- | ---------- | ------------------ | ---------------------- | ------------ |
| 6        | 小型株     | ○    | -          | 有効               | 2件                    | 90日         |
| 7        | 中型株     | ○    | -          | 有効               | 2件                    | 180日        |
| 8        | 大型株     | ○    | -          | 有効               | 2件                    | 270日        |
| 12       | デフォルト | ○    | ○          | **無効**(既定)     | 2件                    | 180日        |

デフォルトグループは削除不可のフォールバック用グループで、候補スクリーニングは既定で無効(タグが一致しない銘柄の買入タイミング/損切り/利確判定にのみ使われる)。

### 4. 候補スクリーニング(自動候補化)

未設定(候補・保有・除外いずれも未設定)の銘柄を、一定の基準を満たした場合に自動で「候補」ステータスへ反映する仕組み。**2系統**が独立して動く。

#### 4.1 系統A: スクリーニングルール(A/B/C分類)による候補化

- 実装: `screening_engine.py` (`evaluate_and_apply`)
- ロジック: 各有効グループの`candidate`ルールのうち、**分類A・分類Bのいずれかに1つでも該当すると、そのグループの候補としては失格**(A・Bは同じ強さのブロック条件、内部的にはOR)。分類Cは現在未使用(参考情報)。
- 失格しなかった銘柄は「候補」となり、根拠グループ名がタグとして付与される(このタグが、後述の買入タイミング/損切り/利確判定でどのグループ基準を使うかの決め手になる)。
- 既にステータスが設定されている銘柄(手動含む)は上書きしない。
- グループを無効化した場合、そのグループのみが根拠で候補になっていた銘柄はステータス・タグをリセットし再評価する。

##### 現状の参考値(分類B、範囲外で失格)

小型株・中型株・大型株の3グループが同一項目セットを使用し、時価総額の区分でセグメント分けしている(デフォルトグループはルール未設定=候補スクリーニング対象外)。

| 項目                | 小型株        | 中型株               | 大型株                  |
| ------------------- | ------------- | -------------------- | ----------------------- |
| ROE(%)              | 10.0 〜 213.6 | 8.0 〜 80.0          | 5.0 〜 40.0             |
| 自己資本比率(%)     | 40.0 〜 97.85 | 35.0 〜 95.0         | 30.0 〜 90.0            |
| 売上高前期比(%)     | 20.0 〜 98.45 | 8.0 〜 40.0          | 0.0 〜 20.0             |
| 売上高営業利益率(%) | 10.0 〜 20.19 | 8.0 〜 18.0          | 8.0 〜 25.0             |
| 時価総額(百万円)    | 60 〜 30,000  | 100,000 〜 1,000,000 | 1,000,000 〜 50,000,000 |

※表は「下限(lte条件の値)〜上限(gte条件の値)」の**範囲内であれば失格しない**ことを示す(範囲外＝分類Bのいずれかに該当＝失格)。中型株はTOPIX Mid400、大型株はTOPIX100・市場平均ROE10.3%を参考に設定。

#### 4.2 系統B: テクニカルスコアによる自動候補化

- 実装: `technical_screener.py` (`apply_score_candidates`)、スコア計算式は`technical_score_settings.py`
- ロジック: 対象銘柄のテクニカルスコア(6要素合計、詳細は5.3節)が**しきい値以上**、かつステータス未設定の銘柄を「候補」として反映する。
- 系統Aとは独立しており、こちらで候補になった銘柄にはタグが付かない(グループ判定のフォールバックはデフォルトグループになる)。
- しきい値変更時は、旧しきい値未満になった候補をリセットして再評価する。

##### 現状の参考値

| 設定項目           | 値           |
| ------------------ | ------------ |
| 自動候補化しきい値 | **60点以上** |

また、実際のスコアに応じて表示用タグ(「高スコア(N点以上)」)が別途、全銘柄に同期される。階層: **100 / 80 / 60 / 40 / 20点以上**。

### 5. 買入タイミング判定

候補(interested)・保有中(holding)・売却済(sold)の銘柄について、「今が買い時か」「買い増し・再エントリーすべきか」を判定する(除外・未設定は対象外)。

- 実装: `trade_judgment_engine.py` (`evaluate_entry`)

#### 5.1 判定ロジック

1. **分類C(条件次第)**: 各条件のうち満たした数を数える。
2. **有力候補判定**: 該当数が「買入シグナル数しきい値」(グループ設定)以上、かつ後述の除外に該当しなければ「有力候補」。
3. **分類A(除外条件)**: 1つでも該当すると、シグナル数がしきい値以上でも強制的に除外する(単日急騰・過熱・上抜け直後などの誤検知防止)。
4. **損切りリスク先読みチェック**: 同じグループの`loss_cut`分類A/Bを、購入前提のnull値(購入価格・購入時スコア無し)のまま評価する。購入価格・スコアに依存する条件(下落率・スコア変化)は自動的に不成立となり、**銘柄自体の状態を示す条件のみ**(上場廃止リスク・監理銘柄・営業利益/EPS成長率の悪化)が働く。
   - 損切り分類A相当に該当 → 買入タイミングの分類Aと同じ強さで**候補から除外**
   - 損切り分類B相当に該当 → 除外はせず**警告表示のみ**

#### 5.2 現状の参考値(分類C・分類A、小型株/中型株/大型株/デフォルト共通)

| 分類 | 項目                           | 条件                                                               | 備考                         |
| ---- | ------------------------------ | ------------------------------------------------------------------ | ---------------------------- |
| C    | MA25上抜け(is_above_ma25)      | true                                                               | 現在値がMA25を上回っている   |
| C    | 出来高倍率                     | 小型株:3.0倍以上 / 中型株:2.5倍以上 / 大型株・デフォルト:2.0倍以上 | 20日平均比                   |
| C    | 決算サプライズ(市場予想乖離率) | 0%以上                                                             | 市場予想を上回った決算       |
| A    | スクリーニングスコア           | 20pt以下で除外                                                     | テクニカルスコア不足の足切り |
| A    | RSI                            | 70以上で除外                                                       | 過熱圏                       |
| A    | MA25乖離率                     | +10%以上で除外                                                     | 追いかけすぎ検知             |
| A    | 前日比騰落率                   | +8%以上で除外                                                      | 単日急騰の誤検知防止         |
| A    | MA25上抜け継続日数             | 2日以下で除外                                                      | 上抜け直後(だまし)の除外     |

**買入シグナル数しきい値**: 全グループ共通で**2件**(3件中、MA25上抜け・出来高急増・決算サプライズのうち2つ以上)。

#### 5.3 テクニカルスコア(screening_scoreの算出式)

買入タイミング判定の`スクリーニングスコア`条件、および候補スクリーニングの系統Bで使うスコアは、以下6要素の加点(一部減点)合計で計算する(`technical_screener.py`)。各要素の配点・期間・閾値はすべて設定画面(テクニカルスコア設定)で編集可能。

| #   | 要素                          | 配点              | 条件                                                          | 現状の参考値                                                                   |
| --- | ----------------------------- | ----------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1   | ステージ2判定(ワインスタイン) | 30点              | 終値 > SMA短期 > SMA長期 かつ SMA長期が上昇トレンド           | 短期SMA=50日 / 長期SMA=200日 / トレンド確認=直近20日比較                       |
| 2   | 相対強度(RS)                  | 25点              | RS = (1+個別株リターン) ÷ (1+ベンチマークリターン) が閾値以上 | 比較期間=126日(約6ヶ月) / 閾値=1.3倍 / ベンチマーク=^N225(日経225)             |
| 3   | 出来高急増                    | 20点              | 直近出来高が平均の一定倍以上                                  | 平均算出期間=20日 / 閾値=1.5倍                                                 |
| 4   | RSI適温ゾーン                 | 15点(過熱時-10点) | RSIが快適圏なら加点、過熱圏なら減点                           | 算出期間=14日 / 快適圏=45〜65 / 過熱判定=70以上                                |
| 5   | VCP・52週高値圏               | 10点              | 52週高値の一定割合以上、またはボラティリティ(ATR/終値)が収縮  | 52週高値閾値=95% / ボラティリティ比較期間=10日 / ATR期間=14日 / 遡及日数=252日 |
| 6   | MACD上昇モメンタム            | 15点              | MACD線がシグナル線を上回る                                    | 短期EMA=12日 / 長期EMA=26日 / シグナル線=9日                                   |

現状の設定では合計最大**115点**(30+25+20+15+10+15)。株価履歴取得期間は2年(`2y`)。

### 6. 損切り判定

保有中(holding)銘柄について、損切りすべきかを判定する。

- 実装: `trade_judgment_engine.py` (`evaluate_loss_cut`)

#### 6.1 判定ロジック

1. **分類A**: 1つでも該当すれば優先度**A(即時売却)**。
2. **分類B**: 分類Aに該当せず、1つでも該当すれば優先度**B(回避・撤退検討)**。
3. いずれにも該当しなければ判定なし(継続保有)。

複数回の買い増しに対応するため、判定に使う「購入価格」「保有数」は`trade_history`全体を口座種別問わず集計した加重平均・合計数量を使う(直近1回の購入記録だけを見るわけではない)。

#### 6.2 現状の参考値(小型株/中型株/大型株/デフォルト共通、score_diffのみグループ別)

| 分類 | 項目                                   | 条件                                                               | 備考                                                                                  |
| ---- | -------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| A    | 上場廃止リスク(is_delisting_risk)      | true                                                               |                                                                                       |
| A    | 監理銘柄フラグ(is_under_supervision)   | true                                                               |                                                                                       |
| A    | 購入価格からの下落率(drawdown_percent) | **-0.5×HV**以下                                                    | HV倍率モード。銘柄自身のヒストリカルボラティリティに応じて動的に閾値が変わる(後述6.3) |
| B    | 営業利益前期比                         | 0%以下                                                             |                                                                                       |
| B    | EPS成長率                              | 0%以下                                                             |                                                                                       |
| B    | 購入時からのスコア変化(score_diff)     | 小型株:-25pt以下 / 中型株・デフォルト:-20pt以下 / 大型株:-15pt以下 | テクニカルスコアの悪化                                                                |

#### 6.3 HV倍率モードについて

`value_mode = hv_multiplier`のルールは、設定値をそのまま閾値とせず、**銘柄自身のHV(ヒストリカルボラティリティ)に対する倍率**として扱う。

```
実際の閾値 = 設定値 × その銘柄のHV
```

HVは60日分の日次リターンの標準偏差を年率換算(√250倍)した値(%)。値動きの荒い銘柄ほど下落率の許容幅が自動的に広がり、値動きの穏やかな銘柄ほど早めに損切りされる。現状は全グループ共通で「-0.5×HV」(例: HV=40%の銘柄なら-20%で損切り、HV=80%の銘柄なら-40%で損切り)。

#### 6.4 派生値の計算式

| 項目                     | 計算式                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------- |
| drawdown_percent(下落率) | (現在値 - 購入価格) ÷ 購入価格 × 100                                                    |
| score_diff(スコア変化)   | 現在のテクニカルスコア - 購入時のテクニカルスコア(購入時点でスナップショット、以後固定) |

### 7. 利確判定

保有中(holding)銘柄について、利確すべきかを判定する。**3つの判定軸**があり、いずれかが成立すれば売却検討となる。

- 実装: `trade_judgment_engine.py` (`evaluate_profit_taking` / `evaluate_holding_period_exit`)

#### 7.1 判定軸1・2: 分類A(ターゲット到達・過熱・トレンド反転・トレイリングストップ)+ 純損益ゲート

1. **分類A**: いずれか1つでも該当すれば売却検討(複数条件はOR)。ターゲットプライス達成度・PER過熱・トレイリングストップ発動に加え、**MA25クロスアンダー(is_below_ma25、現在値がMA25を下回った)**によるトレンド反転シグナルも条件として設定できる(全グループに設定済み、詳細は7.3節)。
2. **純損益ゲート**: 分類Aに該当しても、手数料・税引後の想定純損益が黒字でなければ利確シグナルとして扱わない(`net_profit <= 0`なら`should_take_profit = False`に強制)。額面上ターゲットに達していても、手数料・税金を差し引くと損失になる場合の誤検知を防ぐ。

#### 7.2 判定軸3: 保有期間満了(第3の判定軸、独立)

損切り・利確とは別の第3の判定軸として、「保有期間の上限(グループ設定)を超えたら、損益に関わらず機械的に決済する」という規律ルール。純損益ゲートの対象外(含み損の状態で期間満了しても、損益に関わらず決済対象として表示する)。保有日数は**最初に建てた買付日**(複数回買い増しした場合は最も古い購入日)から起算し、JST(Asia/Tokyo)の日付で計算する。

#### 7.3 現状の参考値(分類A、グループ別)

| 分類 | 項目                     | 小型株   | 中型株    | 大型株    | デフォルト |
| ---- | ------------------------ | -------- | --------- | --------- | ---------- |
| A    | ターゲットプライス達成度 | 100%以上 | 100%以上  | 100%以上  | 100%以上   |
| A    | PER(予想、過熱)          | 65倍以上 | 45倍以上  | 30倍以上  | 60倍以上   |
| A    | トレイリングストップ発動 | true     | true      | true      | true       |
| A    | MA25割れ(is_below_ma25)  | true     | true      | true      | true       |
| -    | 保有期間上限             | **90日** | **180日** | **270日** | **180日**  |
| -    | トレイリングストップ許容下落率 | **15%** | **12%** | **8%** | (全体設定にフォールバック、既定10%) |

PERの過熱閾値はセグメントが小さいほど緩め(小型株は高PERが許容されやすい)に設定。保有期間上限は、モメンタムの持続しやすさに応じてセグメント別に設定(小型株は反転が早いため短め、大型株は機関投資家の資金流入で持続しやすいため長め、詳細根拠は判定基準設定画面のRuleEditor参照)。

MA25クロスアンダーは、目標株価という主観的な基準に頼らず「トレンドが崩れたら機械的に手仕舞う」という技術的な反転シグナルであり、確率論的なモメンタム戦略の考え方(1.5節参照)に沿った条件として全グループに設定している。

#### 7.4 トレイリングストップ

保有中の最高値から一定割合下落したら発動。

```
逆指値ライン = 保有期間中の最高値 × (1 - 許容下落率)
発動条件: 現在値 <= 逆指値ライン
```

許容下落率はグループごとに設定でき(`screening_groups.trailing_stop_allowance_percent`)、未設定のグループは全体設定(`trailing_stop_allowance_percent`、既定10%)にフォールバックする。値動きの荒い小型株はストップに引っかかりやすいため広めに、値動きが安定した大型株は狭めに設定するのが望ましいという考え方に基づき、現状は小型株15% / 中型株12% / 大型株8% / デフォルトは全体設定(10%)としている。

#### 7.5 ターゲットプライス(目標株価)の算出ロジック

利確判定の達成度は、以下の優先順で採用したターゲットプライスを使う。

1. 手動設定値(`target_price_manual`)
2. **購入時点のスナップショット**(`target_price_at_purchase`、購入時に算出し以後固定。現在値変動の影響を受けない)
3. 現在値ベースの自動算出値(`target_price_auto`、保有・候補銘柄の指標更新の都度再計算)

自動算出には3つのロジックがあり、グループごとに優先ロジックを設定できる(データ不足時は他ロジックへフォールバック、既定順は アナリストコンセンサス→EPS成長率ベース→PBR正常化ベース)。

| ロジック                                  | 計算式                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| analyst_consensus(アナリストコンセンサス) | アナリスト目標株価平均をそのまま採用                                     |
| eps_growth(EPS成長率ベース)               | 現在株価(購入時点スナップショットの場合は購入価格) × (1 + 予想EPS成長率) |
| pbr_normalization(PBR正常化ベース)        | BPS × ターゲットPBR(既定1.0倍)                                           |

現状の参考値(グループ別優先ロジック):

| グループ   | 優先ロジック       |
| ---------- | ------------------ |
| 小型株     | eps_growth         |
| 中型株     | analyst_consensus  |
| 大型株     | analyst_consensus  |
| デフォルト | (指定なし、既定順) |

ターゲットプライスが購入価格を上回っていない場合、達成度算出は無効(None)として扱う(下落局面で目標も一緒に下がり、達成率が実態と無関係に押し上げられるのを防ぐため)。

#### 7.6 手数料・税引後の想定純損益(純損益ゲートの計算)

```
純損益 = (売却額 - 売却手数料) - (購入額 + 購入手数料) - 譲渡益課税
譲渡益課税 = max(0, 上記の黒字額) × 税率
```

複数回の買い増しに対応するため、**口座種別(特定・一般口座 / NISA口座)ごとに残存数量・加重平均取得単価を分けて計算し、合算する**。NISA口座は譲渡益非課税・手数料無料として扱う。

##### 現状の参考値

**譲渡益課税の税率: 20.315%**(特定口座(源泉徴収あり)/一般口座、NISAは非課税)

**売買手数料(片道、約定代金の金額帯別、SBI証券の現物取引「スタンダードプラン」を参考に設定)**

| 約定代金    | 手数料  |
| ----------- | ------- |
| 〜5万円     | 55円    |
| 〜10万円    | 99円    |
| 〜20万円    | 115円   |
| 〜50万円    | 275円   |
| 〜100万円   | 535円   |
| 〜150万円   | 640円   |
| 〜3,000万円 | 1,013円 |
| それ以上    | 1,070円 |

※証券会社・プランによって異なるため、実際に利用している手数料表と照合が必要(SBI証券の「ゼロ革命」等、条件を満たすと無料になる制度もある)。

#### 7.7 損切り・利確共通の派生値

| 項目                               | 計算式                                  |
| ---------------------------------- | --------------------------------------- |
| ma25_deviation_percent(MA25乖離率) | (現在値 - MA25) ÷ MA25 × 100            |
| daily_change_percent(前日比騰落率) | (現在値 - 前日終値) ÷ 前日終値 × 100    |
| achievement_percent(達成度)        | 現在値 ÷ 有効なターゲットプライス × 100 |
| is_below_ma25(MA25割れ)            | 現在値 < MA25                           |

### 8. 統合判定(優先順位)

銘柄管理・損切り利確判定画面などでは、上記の判定を1つの統合バッジとして表示する(`frontend/src/lib/tradeSignals.ts`)。優先順位は以下の通り(上にあるほど優先)。

1. 損切り優先度A → **即時売却**(赤)
2. 損切り優先度B → **回避・撤退検討**(オレンジ)
3. 保有期間満了 → **保有期間満了**(オレンジ、純損益に関わらず表示。損切り優先度が付いている場合はそちらが優先表示されるが、詳細画面には両方表示される)
4. 利確シグナル(純損益ゲート通過) → **利確**(緑)
5. 買入タイミング有力候補 → **買い候補**(緑)
6. 上記いずれにも該当しない → 継続保有(バッジなし)
